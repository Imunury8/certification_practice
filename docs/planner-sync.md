# 공부 계획 PC 간 동기화

기존 계획은 브라우저의 `exam-study-planner:v1`에 저장됩니다. 같은 사이트라도 다른 PC나 다른 브라우저에서는 이 데이터를 읽을 수 없습니다.

## Vercel 저장소 연결

1. `certification-practice` 프로젝트의 **Storage → Create Database → Upstash → Upstash for Redis**를 선택합니다.
2. 계정 소유자가 제공자의 약관과 요금제를 확인하고 저장소를 생성합니다. 학습 계획만 저장하므로 사용량에 맞는 최소 요금제를 선택합니다.
3. 이 프로젝트에 저장소를 연결하고 필요한 배포 환경을 선택합니다. 운영 사이트에는 **Production** 환경이 필요합니다.
4. 프로젝트 환경 변수에 아래 중 한 쌍이 추가됐는지 확인합니다.
   - `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`
   - `KV_REST_API_URL` / `KV_REST_API_TOKEN`
5. 변경 코드를 배포합니다. 환경 변수를 나중에 추가했다면 다시 배포해야 합니다.

토큰은 서버 환경 변수에만 넣습니다. `NEXT_PUBLIC_` 변수, 소스 코드, 채팅, 연결 코드 입력란에 데이터베이스 토큰을 넣지 않습니다.

참고: [Vercel Storage](https://vercel.com/docs/storage), [Upstash Redis REST API](https://upstash.com/docs/redis/features/restapi).

## 기존 계획을 옮기고 다른 PC 연결하기

1. **기존 계획을 입력했던 PC와 브라우저**에서 기존과 동일한 사이트 주소의 `/planner`를 엽니다. `localhost`와 운영 사이트는 별도 저장소입니다.
2. 화면에 기존 계획이 보이는지 확인하고 **기존 계획을 동기화하기**를 누릅니다. 현재 계획·완료·복습 기록을 함께 서버에 저장합니다.
3. 발급된 연결 코드를 보관합니다. 다른 PC의 같은 사이트에서 **다른 PC의 계획 연결**에 이 코드를 입력합니다.
4. 이후 서버에 저장을 완료하면 다른 PC에서도 새로 불러오거나 페이지에 다시 돌아왔을 때 반영됩니다.

연결 코드를 아는 사람은 해당 계획을 읽고 수정할 수 있습니다. 코드는 URL에 넣지 않고 요청의 인증 헤더로만 전송됩니다. 데이터베이스에는 코드의 해시를 키로 사용합니다.

## 기록 보호 방식

- 기존 브라우저 저장 데이터는 동기화 후에도 원본으로 남깁니다. 서버 계획과 로컬 계획을 자동으로 합치거나 덮어쓰지 않습니다.
- **이 PC의 기존 계획으로 돌아가기**는 이 브라우저의 연결만 해제합니다. 서버 계획은 그대로 남습니다. 돌아간 로컬 계획은 동기화 시작 당시의 원본이며, 이후 서버에서 수정한 내용까지 반영된 복사본은 아닙니다.
- 서버 연결이 끊기면 마지막으로 불러온 계획을 보여주고 편집을 막습니다. 서버에 저장되지 않은 변경을 저장 완료로 표시하지 않습니다.
- 두 PC가 동시에 저장하면 버전 번호를 비교해 충돌한 요청을 거절합니다. 최신 계획을 불러온 뒤 다시 시도합니다.
- 저장소 설정이 없으면 로컬 저장만 제공하고 화면에서 이 상태를 표시합니다. 동기화가 된 것처럼 표시하지 않습니다.

## 검증

`npm test`, `npm run lint`, `npm run build`를 실행합니다. 실제 배포 후에는 별도 브라우저 두 개에서 같은 연결 코드로 연결한 뒤 일정 추가·수정·완료·삭제와 새로고침 반영을 확인합니다.
